About This Project (Meta / architecture questions)

What predicts the salary figure: The predicted monthly salary is produced
by a machine-learning regression model trained on a dataset of Age, City,
Education, Job Role and Monthly_Salary for freshers. Several regression
models are trained and compared, and the one with the best held-out
accuracy (highest R-squared, ties broken by lower error) is the one this
project actually uses.

Which cities are supported: This project currently supports goal-cost and
salary predictions for 10 Indian cities: Ahmedabad, Bangalore, Chennai,
Delhi, Hyderabad, Jaipur, Kolkata, Lucknow, Mumbai and Pune. A city
outside this list cannot currently be planned for.

How the knowledge-base question feature works: This "Ask a knowledge-base
question" feature is a Retrieval-Augmented Generation (RAG) system that
runs fully locally: your question is compared against chunks of the
project's own written documentation using TF-IDF text similarity, the
best-matching chunks are returned as the grounded answer, and if nothing
matches well enough the system says the information is not available
rather than guessing. No paid embeddings API is used for this matching
step.

What the AI advisor note does: The optional AI advisor note is a short,
plain-language commentary generated by a hosted large language model
(via the Groq API) on numbers that have already been calculated
deterministically elsewhere in the project. The language model is only
ever asked to phrase or explain existing numbers - it is never allowed to
invent, change or recompute a financial figure. If the language model is
unavailable for any reason, a fixed templated message is shown instead so
the rest of the plan is always still usable.

Why work experience is not an input: This project treats all users as
freshers / early-career professionals, so years of work experience is
deliberately never used as an input to the salary prediction model or
anywhere else in the pipeline, even if a user happens to mention it.

Does this project store submitted data: Each request (a plan, an agent
message, or a knowledge-base question) is processed and a response is
returned without being written to a database or file; the project does
not persist individual users' submitted answers between sessions.
